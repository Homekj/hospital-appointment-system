## 排查「依赖已添加但 IDEA 里大量文件爆红」

结论：不是缺 jar。Maven 离线 `clean compile` 显示所有依赖（Spring Boot 4.1.2、mybatis-plus 3.5.18、lombok 1.18.48、jjwt）都在 classpath。真正原因是两个 Java 结构性错误导致 javac 中断注解处理，Lombok 未生成任何 getter/构造器，牵连 18 个实体类 + Result + Controller + ServiceImpl 全红；再叠加 IDEA 的 Maven 模块导入状态丢失。

已修：
- `dao/LoginDao.java` → `dao/UserDao.java`（文件内是 `public interface UserDao`，文件名必须一致）
- `LoginServiceimpl.java`：`private LoginDao loginDao` → `private UserDao loginDao`（LoginDao 类根本不存在）
- `pom.xml`：jjwt-jackson 0.12.6 → 0.13.0（与 api/impl 统一）；spring-boot-starter-validation 去掉手写的 4.1.0 交给 parent 4.1.2；lombok 的 annotationProcessorPaths 两处补 `<version>${lombok.version}</version>` 便于 IDE 解析
- `.idea/misc.xml`：languageLevel JDK_26 → JDK_17（SDK 是 17）

验证：`mvn -o clean compile` 通过，target/classes 生成 27 个 class。

项目要点：
- 本地 Maven 仓库在 `D:\APP\Repository`，Maven home `D:\APP\apache-maven-3.9.11`（settings.xml 配阿里云镜像），不是 `~/.m2`。命令行 `mvn` 不在 PATH，需全路径调用 `mvn.cmd`。
- IDEA `.idea/modules.xml` 只挂了一个手工 JAVA_MODULE，但 compiler.xml / workspace.xml 都引用 `module name="backend"` → 需重新 "Add as Maven Project" 选 `backend/backend/pom.xml` 并 Reload，IDE 才会恢复依赖 classpath 与注解处理（compiler.xml 的 profile 绑定 backend 模块）。
- 遗留运行隐患：`UserDao` 无 `@Mapper`、启动类无 `@MapperScan`（16:07 用户已在启动类补上 `@MapperScan("com.aaa.backend.dao")`）；`application.properties` 中文注释乱码、数据源指向 192.168.0.195（实测可连）、未配 Redis。

## 排查 `/admin/department/findByLileName` 一直 404

结论：**不是路径/代码问题，是 8080 上跑的服务加载了旧字节码**。源码 16:07:45 改过（新增 DepartmentController 等），但 target/classes 里还是 15:48 的编译产物，进程 16:07:49 启动时加载的是旧 class，因此 `@GetMapping` 没注册，请求落到静态资源 handler 后返回 Spring Boot 默认 404 JSON。

验证方法（可复用）：
- 用 `Get-CimInstance Win32_Process` 取运行中 JVM 的 `-classpath`，在 8081 起一个干净实例做对照；注意 PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写 BOM，会让 classpath 首项失效导致 `ClassNotFoundException`，须 `Trim([char]0xFEFF)`，并用参数数组 `@('-cp',$cp,...)` 传给 java.exe（直接写 `-Dfile.encoding=UTF-8` 会被 PowerShell 拆错）。
- `jcmd <pid> GC.class_histogram` 可确认运行中 JVM 是否加载了某个类。
- 带有效 admin token 才能穿透 JwtInterceptor：不带 token → 401，带有效 token 且 role=admin → 才看得到真实 404/200。
- JWT 可用 Python hmac-sha256 手工构造：密钥 `HospitalSystemAdminSecretKey2024ForLogin`，HS256，claims 含 `role=admin`/`userId`/`iat`/`exp`。

对照结果：8081 干净实例 `/admin/department/findByLileName` → 200 `{"code":200,"msg":"success","data":[]}`；8080 旧进程同请求 → 404。`/api/login` GET → 405 说明 LoginController 正常注册。

已改：`DepartmentController.java` 把笔误 `findByLileName` 改为方法名 `findByLikeName`，映射改为 `@GetMapping({"/findByLikeName","/findByLileName"})` 双路径兼容（旧 URL 仍可用）。已 `mvn -o clean compile` 通过（32 个 class），临时 8081 实例已停，未动用户的 8080 进程。用户需在 IDEA 里 Stop → Rebuild → Run 才会加载新 class。

其余：JwtInterceptor 401/403 时 `Result.error()` 固定返回 code=500，前端按 code 判断会误判。
