## 排查 `/admin/department/findByLileName` 一直 404

结论：**不是路径/代码问题，是 8080 上跑的服务加载了旧字节码**。源码 16:07:45 改过（新增 DepartmentController 等），但 target/classes 里还是 15:48 的编译产物，进程 16:07:49 启动时加载的是旧 class，因此 `@GetMapping` 没注册，请求落到静态资源 handler 后返回 Spring Boot 默认 404 JSON。

验证方法（可复用）：
- 用 `Get-CimInstance Win32_Process` 取运行中 JVM 的 `-classpath`，在 8081 起一个干净实例做对照；注意 PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写 BOM，会让 classpath 首项失效导致 `ClassNotFoundException`，须 `Trim([char]0xFEFF)`，并用参数数组 `@('-cp',$cp,...)` 传给 java.exe（直接写 `-Dfile.encoding=UTF-8` 会被 PowerShell 拆错）。
- `jcmd <pid> GC.class_histogram` 可确认运行中 JVM 是否加载了某个类。
- 带有效 admin token 才能穿透 JwtInterceptor：不带 token → 401，带有效 token 且 role=admin → 才看得到真实 404/200。
- JWT 可用 Python hmac-sha256 手工构造：密钥 `HospitalSystemAdminSecretKey2024ForLogin`，HS256，claims 含 `role=admin`/`userId`/`iat`/`exp`。

对照结果：8081 干净实例 `/admin/department/findByLileName` → 200 `{"code":200,"msg":"success","data":[]}`；8080 旧进程同请求 → 404。`/api/login` GET → 405 说明 LoginController 正常注册。

已改：`DepartmentController.java` 把笔误 `findByLileName` 改为方法名 `findByLikeName`，映射改为 `@GetMapping({"/findByLikeName","/findByLileName"})` 双路径兼容（旧 URL 仍可用）。已 `mvn -o clean compile` 通过（32 个 class），临时 8081 实例已停，未动用户的 8080 进程。用户需在 IDEA 里 Stop → Rebuild → Run 才会加载新 class。

其余：JwtInterceptor 401/403 时 `Result.error()` 固定返回 code=500，前端按 code 判断会误判。
