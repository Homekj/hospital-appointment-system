# 2026-11-12 工作日志

## 14:2x 医生端接口后端（/api/doctor）

**背景**：`miniprogram/` 目前只有患者端（`app.json` 无医生页面，`README` 写明用 mock），`utils/request.js` 约定 `Authorization: Bearer <token>` 与返回体 `{ code, data, message }`（`code===200` 才取 data）。医生端按项目既有契约新建，不改前端。

**复用已有能力**：`CurrentUserContext.requireDoctorId()`（JWT sub → sys_user.doctor_id，已校验 role=DOCTOR 且绑定医生）、`RoleAccessPolicy` 的 `/api/doctor → DOCTOR`、`AppointmentContractService` 实现的 `AppointmentQueryService` / `AppointmentCommandService`（`pageForDoctor` 会用入参 doctorId 覆盖 query.doctorId）、`ConsultationRecordDao` + `ConsultationVO`、`AppointmentStatus` 状态机。

**新增 `doctor/` 包 7 个文件**：`controller/DoctorWorkbenchController`、`service/DoctorWorkbenchService`、`dao/DoctorWorkbenchDao`、`vo/DoctorProfileVO|DoctorDashboardVO|DoctorScheduleVO`、`dto/ConsultationSaveRequest`。
**修改**：`appointment/support/PatientMapperScanConfig.java` 的 `@MapperScan` 追加 `com.aaa.backend.doctor.dao`（只增一行；不加新 Mapper 不会注册成 bean）。

**接口**：`GET /me`、`GET /dashboard`、`GET /schedules`、`GET /appointments`、`GET /appointments/{id}`、`GET|PUT /appointments/{id}/consultation`、`PUT /appointments/{id}/start-consultation`、`PUT /appointments/{id}/complete-consultation`。统一返回 `ApiResponse<T>`。

**数据隔离（核心）**：唯一可信身份是 `requireDoctorId()`，前端传的 doctorId 不参与归属判断。列表强制带当前 doctorId；单条读写前先调 `requireOwnership` —— 用**不带 doctorId 过滤**的 `selectAppointmentOwner` 查真实 owner，null → 404、不等于当前 → **403**。这一步不能省：契约自身的 `getDetailForDoctor`/`startConsultation` 越权时只抛 `APPOINTMENT_NOT_FOUND`(404)，不满足「必须 403」。另外显式传他人 doctorId 也走 `assertSameDoctor` → 403，而不是静默忽略。

**状态机**：`checked_in --start--> in_consultation --save病历(按 uk_consultation_appt upsert)--> --complete--> completed/pending_rx_pay`（契约按有无处方决定目标状态）。保存病历仅 `in_consultation` 允许，字段长度按表定义 500/1000/500/1000/500 校验；start/complete 幂等。日期区间固定按就诊日期 `schedule_date`，排班查询最长 366 天、上限 200 条。

**验证**：`mvn -o clean compile` BUILD SUCCESS（138 源文件 / 142 class）；进程内启动 9094 做真实 HTTP 冒烟 **22/22 PASS**：无 token 401、ADMIN token 403、本人各接口 200、跨医生（列表参数/详情/三个写动作/反向）8 个 403、不存在 404、错误状态 400、完整接诊流程 + 幂等 200。测试数据 2 条预约与病历已清理，临时测试类已删除。

**经验**：① 复用契约时被调方越权返回 404 ≠ 需求要的 403，必须在自己模块前置做「不带过滤查 owner」；② 新增按域分包的 Mapper 一定要检查 `PatientMapperScanConfig` 的 basePackages，否则编译过但启动 `NoSuchBeanDefinitionException`；③ 同名/跨模块身份一律从 `CurrentUserContext` 取，绝不信任请求参数。

## 15:xx 按 docs/api.md 调整六个模块 + 三份交付文档

**契约要点**：3.1 统一 `{code,data,message}`、3.2 分页 `{records,total,current,size}` / 参数 `current,size`、3.3 HTTP 状态码 = 业务码、12 章 `/api/admin/**` RESTful、13 章医生端 `/stats|start|clinical|complete|medicines`、17.7 旧 `/admin/**` 只作迁移兼容、17 CORS 白名单。

**核心设计（重要，后续沿用）**：
- 新建 `admin/support/ResultBridge.java`：旧 Service 返回 `Result`（失败 HTTP 200+code=500），通过 `data()/page()` 桥接成 `ApiResponse` / `PageResult`，并按错误文案映射 404（不存在）/409（已存在、重复、无法停用、请勿重复）/400（其余）。**新契约控制器只做参数适配，不复制业务规则**。
- 预约模块本来就占用 `/api/admin/appointments`，就地改造 `AppointmentController`，避免同路径两个 Controller 造成 Spring 映射歧义；`/{id:\\d+}` 正则保护 `/export` 等字面量路径。
- 新增 3 个契约控制器 `admin/controller/Admin{Department,Doctor,Schedule}Controller`；科室/排班缺的能力补进旧 Service 接口（`page/detail/changeStatus`、`detail`），旧 `/admin/**` 一行不改。
- 字段适配：文档 `startDate/endDate` → 旧 `scheduleDateStart/scheduleDateEnd`；`patientName` → `keyword`；`current/size` → `pageNum/pageSize`。批量排班用 `ScheduleBatchRequest.toDto()`。
- 登录/医生管理移除 `@CrossOrigin`（默认任意来源，违反 17 章），CORS 统一走 `WebMvcConfig` 白名单；白名单 allowedHeaders 加 `Idempotency-Key`。远程成员患者端控制器上的 `@CrossOrigin` **未动**（用户此前要求不能影响别人页面），已记为待办。
- 医生端路径全部对齐并把旧路径留作别名；`/stats` 用新 `DoctorStatsVO`（文档四字段），`/dashboard` 仍返回扩展 VO；详情改为 `DoctorAppointmentDetailVO`（预约+病历+处方摘要）。
- 完成接诊开方：`POST /complete` 一个 `@Transactional` 内做归属校验 → 状态/病历/已有处方校验 → 明细去重+启用校验 → `medicineDao.selectBatchIds()` 服务端计价 → 条件更新 `completeAppointment`（`status='in_consultation' AND 排班归属当前医生`）→ 插 `prescription(unpaid)` + 明细快照 → 分流 `pending_rx_pay`/`completed`。`uk_prescription_appt` 兜底，已完成状态走幂等分支返回既有结果。`PrescriptionItemRequest` 刻意不含 `unitPrice/amount`。
- 新增 `doctor/dao/MedicineDao`（放 doctor.dao 复用已有扫描范围），`/medicines` 只查 `status=1 AND stock>0`，keyword 匹配 name/spec。
